# Templates & Frontend

GoForge uses [templ](https://templ.guide/) for type-safe server-side templates and [HTMX 2](https://htmx.org/) for dynamic UI interactions.

## Template Structure

```
internal/web/templates/
├── layouts/
│   └── base.templ         # HTML shell with sidebar, nav, scripts
├── pages/
│   ├── dashboard.templ    # Dashboard with stats cards
│   ├── login.templ        # Login form
│   ├── register.templ     # Registration form
│   ├── projects/          # Project list and detail views
│   ├── deployments/       # Deployment views
│   ├── services/          # Service catalog and instances
│   ├── settings/          # User settings
│   └── errors/            # Error pages (404, 500)
└── components/
    ├── sidebar.templ      # Navigation sidebar
    ├── nav.templ          # Top navigation bar
    ├── form.templ         # Reusable form elements
    ├── modal.templ        # Modal dialogs
    ├── toast.templ        # Toast notifications
    └── ...
```

## Working with templ

### Generating Templates

```bash
# Generate all templates
make templ

# Watch for changes (in a separate terminal)
make templ-watch
```

The `make dev` command handles this automatically via `air`.

### Template Syntax

templ templates are Go files with HTML-like syntax:

```go
package pages

import "github.com/raythurman2386/goforge/internal/models"

templ ProjectList(projects []*models.Project) {
    <div class="grid grid-cols-1 md:grid-cols-2 gap-4">
        for _, p := range projects {
            <div class="card">
                <h3>{ p.Name }</h3>
                <p>{ p.Description }</p>
            </div>
        }
    </div>
}
```

### Type Safety

templ provides compile-time type checking:

- Template parameters are strongly typed
- Go expressions are validated at compile time
- Component composition is checked for correct argument types

### Generated Files

templ generates `*_templ.go` files next to each `.templ` file. These are:

- Excluded from version control (`.gitignore`)
- Excluded from linting (`.golangci.yml`)
- Regenerated by `make templ` or `make build`

## HTMX Integration

HTMX enables dynamic UI without writing JavaScript. Common patterns used in GoForge:

### Partial Page Updates

```html
<button hx-post="/projects/{id}/deploy"
        hx-target="#deployment-status"
        hx-swap="innerHTML">
    Deploy
</button>
```

### Form Submissions

```html
<form hx-post="/projects"
      hx-target="#project-list"
      hx-swap="afterbegin">
    <!-- form fields -->
</form>
```

### Server-Sent Events

```html
<div hx-ext="sse"
     sse-connect="/sse/deployments/{id}/logs"
     sse-swap="message">
    <!-- Logs appear here in real-time -->
</div>
```

### CSRF Token

The base template configures HTMX to send the CSRF token automatically:

```html
<body hx-headers='{"X-CSRF-Token": "..."}'>
```

## TailwindCSS

GoForge uses TailwindCSS for styling.

### Building CSS

```bash
# Build CSS once
make css

# Watch for changes
make css-watch

# Build, then fail on class tokens missing from output.css (same as the CI css job)
make css-check
```

`make css` uses Tailwind v3.4.17, the version the Dockerfile and CI pin: the standalone `tailwindcss` on `PATH` if it reports v3.4.17, otherwise `npx --yes tailwindcss@3.4.17`. It fails (no placeholder CSS) when neither works or when `TAILWIND=...` names another version. `make css-check` deletes `output.css` first, so it never checks a stale file.

`scripts/class_check.py` checks these class sources against `output.css`: literal `class="..."` attributes in `.templ` files and handlers; string literals inside templ `class={ ... }` expressions (including `templ.KV` keys); `return "..."` strings in Go helpers named `*Class` under `internal/web/templates` (`statusBadgeClass`, `alertClass`, `logLevelBadgeClass`, `backupLineClass`, ...); string arguments to `Skeleton`; and in `static/js/app.js`, `LEVEL_CLASSES` values, `.className` literals, and `classList.add/remove/toggle` arguments. A class assembled from a runtime value (for example `"w-" + n`) cannot be checked, and Tailwind would not compile it either: keep every class a complete literal in one of those places.

### Configuration

The Tailwind configuration is in `tailwind.config.js`:

- Scans `.templ` and generated `_templ.go` files for class names
- Uses a green/emerald color palette
- Includes custom font families

### Input and Output

- Input: `static/css/input.css` (Tailwind directives)
- Output: `static/css/output.css` (generated, not committed)

## Adding a New Page

1. Create the templ template in `internal/web/templates/pages/`:

```go
// internal/web/templates/pages/newpage.templ
package pages

templ NewPage(data SomeData) {
    @layouts.Base("Page Title") {
        <h1>New Page</h1>
        // page content
    }
}
```

2. Create or update the handler in `internal/web/handlers/`:

```go
func (h *Handler) NewPage(w http.ResponseWriter, r *http.Request) {
    data := h.service.GetData(r.Context())
    pages.NewPage(data).Render(r.Context(), w)
}
```

3. Add the route in `internal/web/router.go`:

```go
r.Get("/newpage", handler.NewPage)
```

4. Regenerate templates:

```bash
make templ
```
